# actor主合同轻量重绑定实现验证 - 2026-03-16 15:06

## 一、这一步的定位

这一步不是激进 takeover，也不是再加一层旁路 guard。

它的定位非常克制：

> **先把 `actor contract composer` 的最小正式接线做出来，让 replay-grounded task semantics 与 certified corridor support 第一次真实进入 actor 主合同。**

也就是说，这一步修的是：

- `task corridor` 不再只是轻观测；
- `certified registry` 不再只是 telemetry；
- 两者第一次共同生成一个可以真正改写 `target_actor + analytic push` 的 `rebind alpha`。

但这一步刻意没有修：

- `base_actor` 污染；
- 强 takeover law；
- controller stage；
- critic-only 主线；
- Iron Wall 本身。

## 二、具体实现了什么

### 1. 配置层补齐了最小 contract rebind 参数

在 `aletheia_config.py` 中新增：

- `adaptive_imag_actor_contract_rebind_enabled`
- `adaptive_imag_actor_contract_rebind_max`
- `adaptive_imag_actor_contract_rebind_analytic_floor`

同时在 `aletheia_api.py` 的 pure-imag CartPole 默认配置里打开：

- `adaptive_imag_actor_contract_rebind_enabled = True`
- `adaptive_imag_actor_contract_rebind_max = 0.3`
- `adaptive_imag_actor_contract_rebind_analytic_floor = 0.65`

并补进 override allowlist，确保真实 run 可以稳定覆写和落盘。

### 2. imagined batch 内新增了最小 actor contract composer

在 `_build_imagined_batch()` 中，这一步把下列三种量正式接到了同一个 alpha 公式里：

- `task mismatch`
  - 高价值 corridor 内，真实 task corridor gate 越弱、置信度越高，mismatch 越大；
- `certified registry mismatch`
  - 当前 imagined `f_policy` 越不被 certified registry 支持，mismatch 越大；
- `clean contract support`
  - replay-grounded clean target 越可用、越可信，support 越强。

当前第一版公式是：

```text
rebind_alpha
  = rebind_max
    * task_mismatch
    * registry_mismatch
    * clean_contract_support
```

这个公式故意保守，它的语义是：

> 只有当“当前高价值 imagined corridor 的任务语义确实错位、认证集也不支持、并且干净目标足够可信”同时成立时，才允许 actor 主合同发生轻度重绑定。

### 3. rebind alpha 会真实改两个地方

这一步不是 placeholder。`rebind_alpha` 已经真实作用到 actor 主链：

1. `target_actor` 轻度朝 `corridor_semantic_clean_target` 混合
2. `analytic_scale_mask` 额外乘上 `actor_contract_analytic_scale`

也就是：

- 一边轻拉目标；
- 一边轻收油门。

这比之前只在 task corridor 上做轻缩放更进一步，因为它已经开始改 actor 主合同本身，而不只是给一个外围 brake。

### 4. 新增了完整监控面

这一步同时把下列指标接入 imagined batch 和 actor metrics：

- `actor_contract_rebind_alpha_mean`
- `actor_contract_rebind_active_fraction`
- `actor_contract_rebind_pressure`
- `actor_contract_rebind_ready`
- `actor_contract_analytic_scale_mean`
- `actor_contract_target_pre_rebind_mean`
- `actor_contract_target_post_rebind_mean`
- `actor_contract_target_delta_mean`
- `actor_contract_task_mismatch_mean`
- `actor_contract_certified_registry_support_mean`
- `actor_contract_certified_registry_mismatch_mean`
- `analytic_weight_scale_actor_contract`
- `analytic_weight_scale_actor_contract_active`

这意味着下一条真实 run 可以直接回答：

> 当前 light rebind 是真的没激活，还是激活了但力度不够。

## 三、这一步为什么是对的

这一步之所以对，不是因为它“更复杂”，而是因为它第一次让系统的三条语义线开始会合：

1. `critic/internal proposal`
2. `replay-grounded task semantics`
3. `certified corridor support`

以前：

- critic 是主合同；
- task corridor 是轻 brake；
- certified corridor 是旁路认证器。

现在：

- task 与 certified 已经开始共同生成 `rebind alpha`；
- actor 主合同第一次被“任务语义 + 稳定认证”联合改写。

所以这一步的意义不是数值有多强，而是：

> **actor 合同终于开始拥有共享语义主键。**

## 四、这一步没有修什么

这一步必须明确边界，不然很容易误读结果。

它还没有修：

### 1. 没有修 `base_actor`

当前 `base_actor` 仍然主要来自 critic/internal ruler。

所以即使 `target_actor` 已开始被 clean contract 拉动，actor loss 的另一半几何仍未完成重绑定。

### 2. 没有做强接管

当前 `rebind_max=0.3`，`analytic_floor=0.65`，属于有意保守。

这代表：

- 更像 first-pass contract correction；
- 不是 dominant contract takeover。

### 3. 没有改 detector family

没有新增 controller stage，也没有新增 critic-only guard。

因果保持干净：

- 这一步只验证 actor 主合同轻量重绑定本身。

## 六、下一条真实 run 的验收标准

这一步真正要靠真实 run 判定的，不是“是否立刻 solved”，而是下面三件事。

### 1. Light rebind 是否真的激活

重点看：

- `actor/contract_rebind_alpha_mean`
- `actor/contract_rebind_active_fraction`
- `actor/contract_analytic_scale_mean`
- `actor/contract_target_delta_mean`

如果这些几乎不动，下一刀应优先加强 alpha law，而不是加新模块。

### 2. 激活后是否真的压住 actor 主推进器

重点看：

- `actor/weighted_actor_target_mean`
- `actor/weighted_analytic_term_mean`

如果 rebind 指标激活了，但 actor 主推进器仍几乎不变，说明当前 first-pass rebind 力度仍不足。

### 3. late hold 是否改善

重点看：

- `eval 2000 / 2250 / 2500 current`
- `actor/real_policy_kl_to_certified_registry_mean`
- `actor/behavior_policy_kl_to_certified_registry_mean`
- `actor/real_imag_policy_registry_drift_gap`

如果 contract rebind 指标活了，但 `2500 current` 仍明显回撤，那么下一步更可能是：

> **加强 actor contract composer，而不是回 controller，也不是回 critic-only。**

## 七、当前判断

如果把这一步压缩成一句话，我的判断是：

> **修对了，而且第一次真正修到了 actor 主合同层。**

但它目前还是“轻量重绑定”，不是“主合同接管完成”。

因此下一条真实 run 的意义非常明确：

- 不是再找新病；
- 而是判定这条主线是否已经开始有足够的执行力。
