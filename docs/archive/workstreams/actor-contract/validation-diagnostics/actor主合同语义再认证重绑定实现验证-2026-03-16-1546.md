# actor 主合同语义再认证重绑定实现验证

- 时间：2026-03-16 15:46
- 阶段：第二阶段实现收口
- 目标：把 `actor contract rebind` 从“必须先出现 registry mismatch 才能启动”改成“只要 corridor 内出现 task semantic mismatch 或 inflation pressure，就允许 clean contract 接管”

## 本次实现

1. 重写 `aletheia_train.py` 中的 actor contract rebind law：
   - 不再要求 `behavior_policy_certified_registry_available > 0` 才能进入 rebind 主逻辑。
   - 当 registry 不可用时，policy support 退化为中性 `ones`，不再把 registry availability 当成生死开关。
2. 新增三组核心语义量：
   - `actor_contract_semantic_certified_mismatch`
   - `actor_contract_semantic_certified_support`
   - `actor_contract_inflation_pressure`
3. 新的 contract pressure 组合方式：
   - `task mismatch = corridor_mask * (1 - task_gate) * task_confidence`
   - `registry mismatch = corridor_mask * (1 - registry_support)`
   - `semantic_certified_mismatch = 1 - (1 - task_mismatch) * (1 - registry_mismatch)`
   - `inflation_pressure = corridor_mask * inflation_gate * clean_target_confidence`
   - `semantic_pressure = max(semantic_certified_mismatch, inflation_pressure)`
   - `rebind_alpha = rebind_max * semantic_pressure * clean_contract_support`

## 这次修复钉死了什么

1. `registry mismatch` 不再是 actor clean contract takeover 的必要前提。
2. certified corridor 的定义开始从“policy-certified”向“semantic-certified”过渡。
3. rebind 的触发条件从“策略像不像旧注册表”提升为“这段 corridor 在任务语义上是否仍然健康”。

## 当前判断

1. 这次实现是正确的，而且方向与 `v178` 真实 run 的剩余病灶完全对齐。
2. 它修掉的是“contract law 的结构盲点”，不是 late-stage hold 的全部问题。
3. 下一条真实 run 的核心验收点不再是“rebind 是否存在”，而是：
   - `actor_contract_rebind_alpha_mean` 是否显著高于 `1e-4 ~ 1e-3`
   - 高 corridor / 低 registry KL 条件下是否仍能因 semantic pressure 而接管
   - `2000+` current checkpoint 是否显著好于 `v178`

## 剩余风险

1. 这次修的是“接管资格”，还没有直接修到“接管强度是否足够支配 late-stage dynamics”。
2. 如果下一条真实 run 里 alpha 仍然偏小，说明下一层问题将转向：
   - `clean_contract_support` 过弱
   - 或 semantic pressure 已建立，但主合同支配权仍不足
3. 如果 alpha 升起来但分数仍掉，说明问题将进一步收紧到：
   - corridor 内部的语义质量
   - 或 clean target 本身的任务正确性
