# 真实稳定性观测面实现与验证-2026-03-16-1243

## 一、目标

本次实现严格限定在“第一阶段观测面”：

- 补齐真实 rollout 侧的稳定性 telemetry
- 将真实 telemetry 通过 `run_train -> TrainingLoop` 链路送入训练日志
- 在 imagined batch 中正式输出 `real` 与 `real-imag mismatch` 指标
- 不改 actor loss
- 不改 critic loss
- 不改 controller stage
- 不改 takeover law

也就是说，这一刀只做“拆账和仪表盘”，不做控制闭环。

## 二、已实现内容

### 1. eval / real rollout 侧

在 [aletheia_api.py](/Users/zhangsan/Desktop/缸中之脑v5.6/aletheia/aletheia_api.py) 中新增了真实行为 telemetry 聚合：

- `real_behavior_action_entropy_mean`
- `real_behavior_action_switch_rate`
- `real_behavior_action_oscillation_rate`
- `real_corridor_occupancy_fraction`
- `real_corridor_persistence_rate`
- `real_corridor_entry_rate`
- `real_corridor_exit_rate`
- `real_policy_kl_to_certified_anchor_mean`
- `real_policy_certified_anchor_available`

真实 corridor 的第一阶段定义为：

- 以“已认证真实锚 actor”作为 certified anchor
- 在真实 rollout 的 `f_policy` 上计算当前策略到 certified anchor 的 KL
- `KL <= 0.05` 的状态记为处于 real corridor

这是一个克制、可解释、足够外生的第一版定义。

### 2. run_train 传递链路

`eval_fn` 现在会：

- 在 eval 前把 `loop._real_stability_certified_anchor_actor` 暂挂给 agent
- 调用 `_evaluate_agent()` 收集真实 telemetry
- 将 telemetry 一并传给 `loop.set_external_eval_feedback(...)`
- 将 telemetry 展平写入 `eval_history.jsonl`

这样后续诊断就可以直接以 `eval_history.jsonl` 为真实行为源，不再只看 imagined 内部量。

### 3. TrainingLoop 存储与导出

在 [aletheia_train.py](/Users/zhangsan/Desktop/缸中之脑v5.6/aletheia/aletheia_train.py) 中新增：

- 最近一次真实 telemetry 缓存
- 最近一次真实 telemetry step
- certified real anchor actor
- certified real anchor 的 step / eval
- certified telemetry snapshot

并在 `_build_imagined_batch()` 中导出：

- `real_behavior_available`
- `real_behavior_age_steps`
- `real_behavior_action_entropy_mean`
- `real_behavior_action_switch_rate`
- `real_behavior_action_oscillation_rate`
- `real_corridor_occupancy_fraction`
- `real_corridor_persistence_rate`
- `real_corridor_entry_rate`
- `real_corridor_exit_rate`
- `real_policy_certified_anchor_available`
- `real_policy_certified_anchor_age_steps`
- `real_policy_kl_to_certified_anchor_mean`
- `real_imag_corridor_occupancy_gap`
- `real_imag_corridor_persistence_gap`
- `real_imag_policy_anchor_drift_gap`
- `real_imag_stability_disagreement`

其中 mismatch 的第一阶段定义为：

- `real_imag_corridor_occupancy_gap = imag_occupancy - real_occupancy`
- `real_imag_corridor_persistence_gap = imag_persistence - real_persistence`
- `real_imag_policy_anchor_drift_gap = real_anchor_KL - imag_eval_anchor_KL`
- `real_imag_stability_disagreement = max(0, imag_stability_score - real_stability_score)`

这正对应当前系统最关键的新病灶：

> imagined 内稳，不再等价于 real 外稳。

## 四、当前意义

这次实现之后，系统第一次具备了如下能力：

- 同时观察 imagined corridor 与 real corridor
- 在训练日志中直接看到二者的错位
- 用真实认证过的 anchor 来审计真实 rollout 稳定性

因此下一轮真实 run 如果再次出现：

- imagined persistence 仍高
- imagined KL 仍低
- 但 real corridor persistence 已掉

那么“观测合同失真”就不再只是推断，而会变成直接可见的数据事实。

## 五、下一步约束

在看到一轮新的真实 run 之前，不建议直接继续改控制律。

更合适的顺序是：

1. 先起新的真实 pure-imag run
2. 观察 `real` 与 `real-imag mismatch` 曲线
3. 确认晚期主病灶是否稳定表现为：
   - `imag stable`
   - `real unstable`
   - `mismatch sharp rise`
4. 只有这一步被数据坐实后，再决定下一刀是：
   - actor 主目标改写
   - L1 bridge/router 约束
   - 还是更高层的控制面接管

一句话总结：

> 第一阶段不是治病，而是把“imagined 内稳”和“real 外稳”正式分家，并把它们的错位变成可追踪、可验证、可闭环的系统观测量。
