# 行为层观测补齐与验证-2026-03-16-1145

## 目标

在已经完成 `L0/L1/L2/L3` 系统级控制分层之后，当前最需要补齐的是 `@750 -> @1000` 这段 pre-inflation 区间的 `L3 behavior control` 观测量。  
本次实现不继续下新的控制刀，而是先把行为层状态变量补齐，避免后续分析继续混在 `value semantics` 与 `behavior instability` 两类问题里。

## 本次补齐的行为层状态变量

### 1. action entropy

- `behavior_action_entropy_mean`
  - 直接记录 imagined branch 上 actor 的动作熵均值。
- `behavior_action_entropy_preinflation_mean`
  - 只在 `pre-inflation slice` 上统计动作熵。

用途：
- 观察 `@750 -> @1000` 是否先发生 action mode collapse。
- 与后续 `policy KL`、`switch/oscillation` 一起判断是“变硬”还是“乱跳”。

### 2. policy KL to anchor

- `behavior_policy_eval_anchor_available`
- `behavior_policy_eval_anchor_age_steps`
- `behavior_policy_kl_to_eval_anchor_mean`
- `behavior_policy_kl_to_eval_anchor_corridor_mean`
- `behavior_policy_kl_to_eval_anchor_preinflation_mean`

定义：
- anchor 不是旧 controller，也不是 replay teacher。
- anchor 是每次外部 eval 时抓取的一份冻结 actor snapshot。
- 在当前 imagined `policy_features` 上，同时评估：
  - 当前 actor policy
  - eval-anchor actor policy
- 计算 `KL(anchor || current)`，得到当前行为相对上一个外部评估参考点的漂移。

为什么选 eval-anchor：
- 它是最贴近“上一时刻被外部回报认证过的行为策略”的参考。
- 它不需要把 controller 再抬回主线。
- 它直接落在 actor-use 的 `policy_features` 空间，而不是别的侧路空间。

### 3. action switch / oscillation

- `behavior_action_switch_rate`
- `behavior_action_switch_rate_preinflation`
- `behavior_action_oscillation_rate`
- `behavior_action_oscillation_rate_preinflation`

定义：
- switch rate: `a_t != a_{t-1}` 的比例。
- oscillation rate: `a_t == a_{t-2} && a_t != a_{t-1}` 的比例。

用途：
- switch rate 用来看策略是否开始频繁换挡。
- oscillation rate 用来看是否出现典型的左右来回摆动式策略振荡。

### 4. corridor occupancy persistence

- `behavior_corridor_occupancy_fraction`
- `behavior_corridor_persistence_rate`
- `behavior_corridor_entry_rate`
- `behavior_corridor_exit_rate`

定义：
- corridor 仍使用当前 actor-use high-value corridor 定义。
- occupancy: 当前 batch 内有多少状态落在 corridor。
- persistence: 已在 corridor 的状态，下一步仍留在 corridor 的比例。
- entry / exit: 从非 corridor 进入、以及从 corridor 离开的转移比例。

用途：
- 区分“策略本身在 corridor 内变坏”与“策略先离开 corridor，之后才坏”。

### 5. pre-inflation `f_policy` 运动学量

- `behavior_f_policy_velocity_mean`
- `behavior_f_policy_velocity_corridor_mean`
- `behavior_f_policy_velocity_preinflation_mean`
- `behavior_f_policy_acceleration_mean`
- `behavior_f_policy_acceleration_preinflation_mean`
- `behavior_f_policy_curvature_preinflation_mean`

定义：
- 以 actor 实际使用的 `policy_features` 作为 `f_policy` 轨迹。
- velocity: `||f_t - f_{t-1}||`
- acceleration: `||f_t - 2 f_{t-1} + f_{t-2}||`
- curvature: `acceleration / (velocity_{t-1} + velocity_t + eps)`

用途：
- velocity 看轨迹是否开始突然加速。
- acceleration 看是否出现明显二阶拐点。
- curvature 看轨迹是否从平顺 corridor 进入急弯状态。

## pre-inflation slice 的定义

本次统一使用：

`pre-inflation slice = corridor_mask × (1 - inflation_gate)`

理由：
- 我们当前要钉死的是 `inflation` 还没有主导之前，行为层是否已经先开始失稳。
- 如果直接全局统计，会被 late inflation 区间稀释。
- 如果只看 corridor，不排除已经进入 semantic inflation 的后段污染。

因此这个切片代表的是：
- 仍在 high-value corridor
- 但还没有进入 semantic inflation takeover 区间

这正是当前 `@750 -> @1000` 需要重点观察的行为窗口。

## 实现落点

- `aletheia/aletheia_train.py`
  - 新增分布 KL 解析辅助函数
  - `TrainingLoop` 增加 behavior eval anchor snapshot 状态
  - `set_external_eval_feedback()` 在每次外部 eval 时抓取 behavior anchor
  - `_build_imagined_batch()` 内直接构造并上报所有行为层指标
- `aletheia/tests/test_training_loop_integration.py`
  - 新增一条集成测试，验证：
    - entropy
    - KL to eval anchor
    - action switch
    - oscillation
    - corridor persistence
    - pre-inflation `f_policy` velocity / acceleration / curvature

## 当前结论

本次不是新修复，而是把下一阶段诊断所需的 `L3` 观测面补齐了。

现在已经可以在真实 run 的 `@750 -> @1000` 区间直接对账：

1. 策略是否先失熵或先变硬
2. 策略是否先偏离 eval-anchor
3. 动作是否先开始 switch / oscillation
4. 是否先离开 corridor
5. `f_policy` 是否先出现速度、加速度或曲率异常

这意味着下一步可以正式从“凭感觉怀疑 behavior instability”，推进到“逐变量对账 pre-inflation 行为病理”。
