## 本次 run 的核心诊断
### 诊断一：L3 行为漂移确实存在，而且能早于强 inflation 出现
- 这点在 `500 -> 1000` 已经被观察到
- 因此“只修 late inflation”不够

### 诊断二：但更深的问题不是 actor 参数单独跑飞，而是观测量失真
- `1500 -> 2250` 的决定性现象是：
  - `policy KL to eval anchor` 很低
  - `imagined corridor persistence` 很高
  - `preinflation behavior` 没出现灾难级塌陷
  - 真实 eval 却显著崩落
- 这说明：
  - actor 在 imagined 使用空间里“看起来还在合理 corridor”
  - 但这个 corridor 对真实 rollout 已不再有同样含义

### 诊断三：主病灶已不能再简化为单纯 actor-side instability
- 当前更准确的说法应是：
  - `actor / critic / bridge / replay` 共同形成的慢反馈，把系统推到一个“imagined 内稳、real 外坏”的错位稳态
- 其中：
  - `actor` 是推进器
  - `critic` 提供被污染的 semantic ruler
  - `replay` 把错误行为分布写回数据面
  - `wm/bridge` 在 Iron Wall 外侧吸收这种慢反馈，逐步改变 actor-use space 的几何意义

## 控制论层面的最新判断
### 当前真正坏掉的，不是单个模块，而是控制系统的“观测合同”
- 当前晚期仍被系统拿来当主观测量的量包括：
  - `imagined corridor persistence`
  - `policy KL to eval anchor`
  - `inflation-aware clean target blend`
- 这些量在晚期都还能给出“系统并未失控”的表象
- 但真实 eval 已经明显证明：
  - 它们不再可靠地代表真实 corridor hold

### 所以更高层的根因不是“缺更多刹车”
- 而是：
  - 控制器正在看一组已经失真的内部观测量
  - 并把它们当作真实稳定性的代理指标

## 对下一刀的约束
### 不应该做的
- 不继续回到 controller-rescue 主线
- 不回到 critic-only 主线
- 不继续只加厚 clean-target takeover
- 不继续把 imagined corridor persistence 当最终被控量

### 应该做的
- 正式把“真实 corridor hold”与“imagined corridor hold”拆成两个状态量
- 引入面向真实 rollout 的外部稳定性观测，至少要覆盖：
  - `policy-to-real-anchor drift`
  - `real corridor occupancy / persistence`
  - `real vs imag corridor mismatch`
  - `anchor-certified state slice` 上的行为保持度
- 下一刀最干净的层级，不再是 L2 单独修补
- 而是：
  - 先在系统级控制蓝图中补一个“真实稳定性观测面”
  - 再决定 actor 主目标该受哪一组观测量支配

## 一句话结论
- `v174` 把病情进一步钉死了：
  - 早期存在真实的 L3 行为漂移
  - 晚期则出现更深的“imagined 内部稳定性观测失真”
  - 当前系统晚期最大的结构问题，不是没有刹车，而是还在拿失真的内部量当真值仪表盘
