# 严重通胀主导接管设计说明-2026-03-16-1037

## 一、当前判断

`v172` 已经把问题收得很窄：

- `inflation_gate` 能拉高
- clean target 能进入 actor 主链
- `floor + bonus` 也已经真实接上

但最终仍然失败，说明剩余主问题已经不是：

- detector 没报警
- support-extension 没覆盖
- controller 没接管
- critic-side 锚完全无效

当前剩余主问题是：

> 在 severe inflation slice 中，clean target 虽然进入了 actor 主链，但仍只是弱阻尼项，而不是足以压过污染 target 的主导合同。

## 二、为什么 `v172` 还不够

`v172` 的 actuator 仍然主要由：

```text
floor + bonus
```

决定，它修掉了 `neg_adv` 作为硬开关的问题，但还保留了两个剩余压缩源：

1. `corridor_mask` 仍会把接管范围限制在 top-quantile
2. 接管强度仍主要看 gate，而没有直接看 actor 实际训练目标 `target_actor_raw` 和 `clean_target` 的数值错位幅度

于是就出现了 `v172` 的典型现象：

- blend 比 `v171` 更早更稳定
- 但污染 `target/base` 的原始量级仍继续膨胀
- 最终 `weighted_actor_target_mean` 还是被污染目标主导

## 三、下一刀的目标

下一刀只做一件事：

> 让 severe inflation 下的 clean target replacement 不再只是“被 gate 允许的一点修正”，而是按 `raw target vs clean target` 的错位幅度自动增强成主导替代。

这刀继续满足现有约束：

- 只动 actor-side 主合同
- 不回 controller rescue
- 不回 critic-only 主线
- 不新增 detector family
- 不动 world model / iron wall
- 不首发修改 `base_actor`

## 四、最小实现公式

保留 `v172` 现有的：

```text
alpha_floor + alpha_bonus
```

再增加一条更直接的 dominant takeover 通路：

```text
target_gap = relu(target_actor_raw - clean_target)
target_gap_need = target_gap / (abs(target_actor_raw) + abs(clean_target) + 1)

dominant_alpha =
    clean_target_blend_max
    * inflation_gate
    * clean_target_confidence
    * target_gap_need

final_alpha = max(alpha_floor + alpha_bonus, dominant_alpha)
```

然后仍然用：

```text
target_actor = lerp(target_actor_raw, clean_target, final_alpha)
```

## 五、这个公式为什么更对

它直接修正了 `v172` 的两个剩余问题：

### 1. 不再只看“门是否打开”，而是看“污染目标到底偏离了多少”

如果 `target_actor_raw` 已经远高于 `clean_target`，那么即使 `neg_adv`、corridor 切片均值之类的量还不够强，dominant path 也会直接把 takeover 拉高。

### 2. 不再让 corridor quantile 决定 severe inflation 高权重前缀能不能被替换

dominant path 只依赖：

- `inflation_gate`
- `clean_target_confidence`
- `target_raw vs clean_target` 的错位幅度

一旦这些条件成立，clean target 就可以直接对 actor 真正要优化的 `target_actor_raw` 形成强接管，而不是继续被 top-quantile corridor mask 限死。

## 六、明确不改什么

本轮刻意不改：

1. `base_actor`
2. critic loss
3. controller
4. support-extension 逻辑
5. detector family
6. 任何 world-model / bridge / router 主链

原因很简单：

- 当前最需要验证的是：  
  **只把 target-side clean takeover 从弱阻尼升级成强替代，是否就足以显著压下 actor 主推进器。**

如果这刀仍不够，再进入下一层：

- `base_actor` 污染
- actor analytic geometry
- 或更深的 bridge/router corridor hold

## 七、验收标准

### 机制级

本地合成测试必须证明：

1. 在相同 inflation/confidence 条件下，`target_actor_raw` 与 `clean_target` 的错位越大，`blend_alpha` 越高
2. 对应的 `target_actor` 必须被更明显地拉向 `clean_target`
3. 现有 floor takeover 行为不能被破坏

### 工程级

必须通过：

1. 针对性 `unittest`
2. 相关 integration tests
3. `py_compile`

### 行为级

下一条真实 run 重点看：

1. severe inflation slice 中 `clean_target_blend` 是否明显高于 `v172`
2. severe inflation slice 中 `target_mean / weighted_actor_target_mean` 是否被真实压下
3. `2500` current checkpoint 是否不再像 `v172` 那样自由落体
