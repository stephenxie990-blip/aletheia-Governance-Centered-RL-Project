# 真实高回报回廊重绑定方案 - 2026-03-16 13:31

## 一、问题定义

`v175` 已将当前主病灶收敛为：

- imagined 行为空间可以保持几何稳定；
- imagined corridor persistence 也可以保持很高；
- 但真实回报已经明显塌陷。

这意味着系统当前稳定住的，不再一定是“真实高回报回廊”，而更像是“内部自洽但任务语义漂移的 imagined corridor”。

因此第一阶段修复目标不是再补一个外层控制器，而是把 actor 主推进器重新绑定到一个更真实的任务语义观测上。

## 二、第一阶段目标

在不新增 trainable head、不新增 controller stage 的前提下，构造一条：

`reference_real_batch (policy_features + value_real MC)`  
`-> replay-grounded task corridor prototypes`  
`-> imagined task_corridor_score / gate / analytic_scale`  
`-> actor analytic push`

核心要求：

1. 新观测发生在 actor-use feature space。
2. 高/低任务语义锚来自 replay 真实回报，而不是 critic 自举值。
3. 低置信度时尽量不干预，避免把早期学习直接压死。
4. 尽量复用现有 `clean target` 与 `analytic_scale_mask` 主链，不再添加新阶段机理。

## 三、实现思路

### 1. 真实原型

在 `reference_real_batch` 上使用：

- `policy_features`
- `value_real`（优先 full MC return）

按 quantile 切出：

- `high-return prototype`
- `low-return prototype`

原型空间就是 actor 实际使用的 feature space，不另起中间表征。

### 2. imagined 任务语义分

对 imagined `policy_features` 计算：

- 到高回报原型的相似度 `high_similarity`
- 到低回报原型的相似度 `low_similarity`
- `task_corridor_score = high_similarity - low_similarity`

再用 replay 自身的高/低样本分数来估计：

- 分离度 `separation`
- 置信度 `confidence`
- 自适应阈值 `score_threshold`

最终得到：

- `task_corridor_gate`
- `task_corridor_analytic_scale`

直觉上：

- 更像真实高回报 corridor：scale 接近 1
- 更像真实低回报 corridor：scale 降低
- 高低原型分不开时：confidence 低，scale 退回接近 1

### 3. actor 接线

第一阶段只改 actor analytic 主推进器：

- 将 `task_corridor_analytic_scale` 与现有 `analytic_scale_mask` 相乘
- 不修改 world model 或 critic 的优化路径
- 不替换现有 clean target，只让它继续作为 inflation 区域的补充合同

这样就能把“真实任务语义”直接接入主油门，而不是继续停留在报警层。

## 四、指标设计

第一阶段至少输出以下指标：

- `actor/task_corridor_score_mean`
- `actor/task_corridor_gate_mean`
- `actor/task_corridor_active_fraction`
- `actor/task_corridor_confidence_mean`
- `actor/task_corridor_high_return_similarity_mean`
- `actor/task_corridor_low_return_similarity_mean`
- `actor/task_corridor_real_separation`
- `actor/task_corridor_score_threshold`
- `actor/task_corridor_analytic_scale_mean`
- `actor/high_value_but_low_task_fraction`
- `actor/task_geom_corridor_disagreement`

重点不是把指标做多，而是让它们能对齐这句判断：

> 当真实高回报语义丢失时，task corridor 指标必须先掉，而不是继续绿灯。

## 五、成功判据

### 机制级

1. replay 高回报/低回报原型能形成正分离度。
2. imagined batch 中能出现非零 `high_value_but_low_task_fraction`。
3. actor loss 主链可以读取并消费 `task_corridor_analytic_scale`。

### 诊断级

1. 当内部高价值 corridor 与真实高回报语义错位时，`task_corridor_gate` 必须下降。
2. `task_geom_corridor_disagreement` 必须能显示“几何仍稳但任务语义已掉”。

### 工程级

1. 现有 clean-target / actor loss / run_train 合同测试不回退。
2. 新增测试覆盖：
   - scorer 在高/低回报 replay 上能分离；
   - task gate 能压低 analytic scale；
   - 低置信度时不会过度压制 actor。

## 六、明确不做

第一阶段不做以下事情：

1. 不新增 trainable scorer/head。
2. 不新增 controller rescue stage。
3. 不回去扩 critic-only anchor 路线。
4. 不回到 bridge-first 主线。
5. 不同时改 actor target replacement 与 critic loss，避免因果混杂。

## 七、风险

### 风险一：早期原型分离度不足

如果高低回报 replay 自身分不开，task gate 可能误伤前期学习。

应对：

- 引入 `confidence` 衰减；
- 低分离度时让 analytic scale 退回接近 1。

### 风险二：仅靠 analytic scale 仍不足

如果 gate 明显下降，但 actor 仍能沿其他支路推进，则说明下一阶段要进一步进入 target branch。

但那是第二阶段问题，不在本次首刀里解决。

## 八、本次实施标准

本次代码实现完成后，必须完成：

1. 配置接线；
2. imagined batch scorer 与指标输出；
3. actor analytic 接线；
4. 单元/集成测试通过；
5. 基于本次实现结果给出“是否值得开真实 run”的明确结论。
