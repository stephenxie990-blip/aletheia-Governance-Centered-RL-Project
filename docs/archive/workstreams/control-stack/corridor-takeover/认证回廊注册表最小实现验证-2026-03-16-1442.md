# 认证回廊注册表最小实现验证 - 2026-03-16 14:42

## 一、这一步为什么先做它

`v177` 已经把一个结构性矛盾暴露得很清楚：

- `step 2000 eval = 500`
- 但旧 `certified corridor` telemetry 仍可能给出低 occupancy / 高 KL

这说明当前系统的问题，不只是 actor 合同和 task 语义分裂；
还包括：

> **稳定认证本身仍在用“单点锚”的窄定义。**

所以这一步不直接继续下 actor 行为刀，而是先把：

- `certified corridor`
- `eval telemetry`
- `imagined observability`
- `resume state`

统一切到一套最小可用的 `registry` 表达。

## 二、这一步具体实现了什么

### 1. 训练侧：`single certified anchor -> certified registry`

在 `TrainingLoop` 中新增了最小多锚注册表能力：

- 保存一组冻结 actor 快照，而不是只留一个 `_real_stability_certified_anchor_actor`
- 同步保存：
  - `step`
  - `eval`
  - `sanitized telemetry`
- 对 registry 做固定上限裁剪，当前默认按最近认证窗口保留

同时补上了此前缺失的持久化链路：

- `adaptive_controller_state` 现在会导出 `real_stability_certified_registry_entries`
- `resume` 时会重建 registry actor bank
- 恢复后单锚兼容字段会指向 registry 最新条目

这一步的意义是：

> **certified corridor 终于不再是“内存里的一根旧指针”，而是可恢复、可继承的系统状态。**

### 2. 评估侧：对 registry 做集合判定

`_run_episode_agent_with_telemetry()` 现在支持：

- 单锚兼容路径：`_real_stability_eval_anchor_actor`
- 新 registry 路径：`_real_stability_eval_anchor_registry_actors`

评估时新增规则：

- 对每个 `f_policy`，计算当前策略到 registry 中任一锚的最小 KL
- corridor membership 不再只看单锚
- occupancy / persistence / entry / exit 可基于 `any-anchor membership` 来定义

新增 telemetry：

- `real_policy_kl_to_certified_registry_mean`
- `real_policy_certified_registry_available`
- `real_policy_certified_registry_size`

这一步的意义是：

> **认证器终于开始对“证书集合”做判断，而不是对某个历史点做膜拜。**

### 3. imagined side：registry support / mismatch 被显式暴露

在 `_build_imagined_batch()` 中，新增了 imagined actor-use feature 对 registry 的最小 KL 对账：

- `behavior_policy_kl_to_certified_registry_mean`
- `behavior_policy_certified_registry_support_fraction`
- `behavior_policy_certified_registry_corridor_support_fraction`

同时新增最小的 `actor contract composer` 观测接口，但暂时不驱动行为修改：

- `actor_contract_certified_registry_support_mean`
- `actor_contract_certified_registry_mismatch_mean`
- `actor_contract_rebind_pressure`
- `actor_contract_rebind_ready`
- `actor_contract_rebind_alpha_placeholder`

这一步的意义是：

> **系统现在终于能在 imagined batch 内直接回答：当前 actor-use corridor，到底有没有被已认证的真实高回报 corridor 支持。**

## 三、这一步没有做什么

这次刻意没有做三件事：

1. 没有把 registry 直接强接进 actor 主目标  
   还没有改 `target/base/analytic_term` 的主合同。

2. 没有新增 controller stage  
   仍坚持“不回 controller-first”的主线。

3. 没有回到 critic-only 修补  
   registry 是稳定认证层，不是 value 自举层的替代物。

也就是说，这一步是：

> **先把“认证参考系”从单点修成集合，再决定它如何干净地进入 actor 主合同。**

## 五、当前最新判断

这一步修复之后，系统能力边界更清楚了：

### 已经修到的层

- `certified corridor` 不再只能用单锚表达
- 真实 telemetry / imagined observability / resume state 三者已经被 registry 统一
- 现在可以区分：
  - 没有认证集
  - 有认证集但当前 imagined corridor 不受支持
  - registry support 存在，但 task semantics 仍在错位

### 还没修到的层

当前 actor 仍主要优化：

- critic/internal proposal
- task corridor 轻缩放

而不是：

- replay-grounded task semantics
- certified corridor support

共同组成的重绑定主合同。

所以这一步之后，最干净的下一层仍然是：

> **把 registry support / mismatch 作为 actor contract composer 的正式输入，而不是停留在 telemetry 和 placeholder pressure。**

## 六、下一步建议

下一刀仍然不该是“再加 guard”，而应是：

1. 先用新 registry 指标跑一轮真实观察，确认：
   - solved-band 内是否确实出现“单锚不支持但 registry 支持”的切换
   - imagined high-value corridor 是否真的长期游离于 registry 外

2. 再把：
   - `task corridor disagreement`
   - `certified registry mismatch`

   共同送入一个最小 `actor contract composer`

3. 第一版只做：
   - contract pressure / alpha 的真实接线
   - 不直接大幅 takeover

这样可以继续保持：

- 因果干净
- 结构优雅
- 不把当前已经验证有效的 `v177` 主线打散
