# AIA-ACSC-v3设计说明书-2026-03-16-0955

## 一、设计结论

下一刀应定义为：

> **AIA-ACSC-v3：通胀主导的干净目标接管**

当前不再新增 detector，不再回 controller，不再回 critic-only，也不继续主修 coverage。

当前唯一应被主修的点是：

> **clean target 已经能进入 actor 链路，但 takeover law 仍然太弱，导致干净目标无法在 high-inflation corridor 中获得真正的主导权。**

## 二、为什么下一刀必须打在 takeover law

### 1. 已被真实 run 证实的部分

#### `v170`

- `best eval = 283.0 @ 1750`
- `current checkpoint = 249.4 @ 2500`

这证明：

- actor-side replay-grounded clean target 主线是对的
- `AIA-ACSC-v2` 不是伪命题，而是能显著改变 late-stage 失稳形态

#### `v171`

- `best eval = 120.0 @ 2250`
- `current checkpoint = 79.8 @ 2500`

同时内部量显示：

- `inflation_gate_mean = 0.9756`
- `clean_target_blend_mean = 0.0626`
- `weighted_actor_target_mean = 0.5664`

这说明：

- 风险 detector 已经几乎拉满
- clean target 已经进入 actor 链路
- 但 actor 主推进器仍主要在优化污染 target

因此，当前的主病灶已不再是：

- detector 是否成立
- replay clean target 是否可用
- support 是否覆盖到 rollout 尾部

而是：

- **为什么 clean target 进入后仍无法 takeover actor 的主推进器**

### 2. 当前结构的核心矛盾

当前 `clean_target_blend_alpha` 的结构是：

```text
alpha =
    clean_target_blend_max
    × corridor_mask
    × neg_adv_gate
    × inflation_gate
    × confidence
```

这在逻辑上很纯，但在工程上太容易被层层稀释。

尤其关键的是：

- `neg_adv_gate` 来自 `advantages = returns - base_actor`
- `base_actor` 本身仍然来自污染 critic family 的 actor-use 标尺

于是当前系统存在一个结构矛盾：

> **让旧尺子决定新尺子能不能说话。**

这会造成：

- 即使 `inflation_gate` 很高
- 即使 `confidence/support` 很好
- 只要 `advantage` 暂时回正
- clean target takeover 就会被迅速压回去

这正是 `v171` 中段和后段反复出现的现象。

## 三、v3 的设计目标

`v3` 只做一件事：

> **把 clean target takeover 从“乘法弱门控的可选修正”，升级为“absolute inflation 主导下的默认接管”。**

对应的合同重写原则是：

1. `absolute inflation` 是 clean target 接管的第一驱动力
2. `negative advantage` 不再是生死开关，只是加码器
3. `corridor + inflation + confidence` 一旦成立，clean target 至少要拿到一个基础接管份额
4. 第一版不动 `base_actor`
5. 第一版不动 critic loss、controller、support-extension 逻辑

## 四、v3 的最小公式

### 当前 v2

```text
alpha_v2 =
    alpha_max
    × corridor
    × neg_adv
    × inflation
    × confidence
```

### 建议的 v3

```text
alpha_floor =
    floor_max
    × corridor
    × inflation
    × confidence

alpha_bonus =
    (alpha_max - floor_max)
    × corridor
    × inflation
    × confidence
    × neg_adv

alpha_v3 = clamp(alpha_floor + alpha_bonus, 0, alpha_max)
```

其中：

- `corridor`：高价值 corridor mask
- `inflation`：absolute inflation gate
- `confidence`：clean target support/confidence
- `neg_adv`：negative advantage gate

### 这个公式的物理意义

#### `alpha_floor`

- 只要系统已经确认：
  - 在高价值 corridor 内
  - 发生了 absolute inflation
  - clean target 有足够 support
- 那么 clean target 就自动获得一个基础接管权

#### `alpha_bonus`

- 如果此时 `advantage` 也明显转负
- 再进一步加强接管力度

因此：

- `inflation` 成为主驱动
- `neg_adv` 退居调制项

## 五、第一版参数建议

第一版坚持克制，只新增一个参数：

- `adaptive_imag_idle_corridor_clean_target_inflation_floor_max`

建议默认值：

- `floor_max = 0.2`

保留现有：

- `clean_target_blend_max = 0.8`
- `negative_adv_threshold = 1.0`
- `negative_adv_tau = 2.0`
- `inflation_threshold = 5.0`
- `inflation_tau = 3.0`
- `corridor_quantile = 0.75`

### 为什么 `floor_max = 0.2`

原因：

- 太小：等于没修
- 太大：会在 inflation 刚冒头时就过度 takeover

`0.2` 的含义是：

- 只要通胀成立，clean target 至少拿到 20% 基础接管份额
- 如果 negative advantage 也明显成立，才继续向 `0.8` 上限逼近

这属于：

- 轻症轻治
- 重症重治

## 六、第一版明确不改什么

`v3-A` 第一版刻意不改以下项目：

1. 不改 detector family
2. 不改 support-extension 逻辑
3. 不改 corridor mask 定义
4. 不改 `base_actor`
5. 不改 critic loss
6. 不改 controller
7. 不新增 stage
8. 不增加新的并联 guard 机制

原因：

- 当前最重要的是验证：
  - **剩余主问题是否真的就是 takeover strength**
- 如果第一版同时改多个变量，会破坏因果清晰度

## 七、为什么第一版不动 `base_actor`

`base_actor` 的污染问题是真实存在的，但不应和 `v3-A` 一起首发。

理由：

1. 动 `base_actor` 会直接改变 actor 几何
2. 因果会比改 `target_actor` 更复杂
3. 很容易把当前已经成立的主线打乱
4. 现在更应先验证：
   - **仅靠 strengthening takeover law，能否显著改善 late-stage hold**

因此当前策略应是：

- 先把 `target_actor` takeover 真正做强
- 如果效果明显但仍有残余问题
- 再作为下一层问题审 `base_actor`

### 2. 更重要的是 inflation-active slice

`v3` 是否打中，不能只看全局均值。

更关键的是：

> **当 `inflation_gate` 高时，clean target blend 是否明显升起，且 weighted actor target 是否被真实压下。**

因此建议新增或离线抽取切片指标：

- `blend_mean_when_inflation`
- `weighted_actor_target_mean_when_inflation`
- `clean_target_confidence_mean_when_inflation`
- `adv_mean_when_inflation`

## 九、成功判据

`v3-A` 的成功，不以更高峰值为第一标准，而以“主接管是否真正接上”为第一标准。

### 机制级成功

当 high-inflation corridor 出现时：

1. `clean_target_blend_mean` 必须显著高于 `v171`
2. 高 inflation 切片中的 blend 不应再贴近 `0`
3. `weighted_actor_target_mean` 必须显著下降

### 动态级成功

相对 `v171`，应看到：

1. `inflation_gate` 拉高时，blend 不再被压成极小值
2. actor 主推进器在高 inflation 时不再长期维持强正值
3. `late-stage value_gap_abs` 放大速度变慢

### 结果级成功

至少满足以下之一：

1. `2500 current checkpoint` 明显高于 `79.8`
2. 最好不低于 `v170 = 249.4`
3. 同时尽量保留 `v171 @750 = 43.6` 这种 coverage 改善

## 十、失败分叉判据

### 情况 A

- blend 明显升起了
- weighted actor target 明显被压下了
- 但 hold 仍然不好

说明：

- takeover law 已不是主问题
- 下一层更可能在：
  - `base_actor` 污染
  - actor analytic geometry
  - 或更深的 bridge/router corridor hold

### 情况 B

- inflation 很高
- blend 仍没明显升起

说明：

- floor 仍不够
- 或 floor 公式仍被别的门控压制

下一步应继续在 `takeover law` 内部调结构，而不是换主线。

### 情况 C

- 早期学习明显变慢
- 但后段也没改善

说明：

- `floor_max` 过大
- 或 inflation 触发过早

应优先回调 `floor_max`，而不是推翻 v3 主线。

## 十一、实施步骤

### v3-A：最小版

1. 新增 `clean_target_inflation_floor_max`
2. 将 `clean_target_blend_alpha` 从纯乘法式改成 `floor + bonus`
3. 其余逻辑全部不动
4. 开一条新的真实 pure-imag run
5. 重点检查：
   - high inflation 时 blend 是否显著升高
   - weighted actor target 是否显著被压下
   - `2500 current checkpoint` 是否明显高于 `v171`

### v3-B：若 A 有效但仍不够

候选只做二选一：

1. 适度上调 `floor_max`
2. 当 `inflation_gate > 某阈值` 时允许 floor 再上浮一档

### v3-C：若 A 已证明 takeover law 成立，但仍有残余问题

再审：

- `base_actor` 的 clean-aware 修正
- 或 actor analytic geometry 中 `target/base` 的重排

但这些都不应与 `v3-A` 一起首发。

## 十二、最终判断

当前已经可以非常明确地说：

1. `AIA-ACSC-v2` 修的是对的层
2. `v170` 证明 actor-side clean target 主方向成立
3. `v171` 证明 support-extension 也修对了子问题
4. 当前剩余主问题已经不再是：
   - clean target 能不能进来
   - detector 能不能报警
5. 当前剩余主问题是：

> **clean target 在 high-inflation corridor 中没有获得足够早、足够强、足够持续的 takeover 权。**

因此：

> **下一刀应直接实现 `AIA-ACSC-v3`，只重写 takeover law 为 inflation-dominant floor + neg_adv bonus，其余机制全部保留。**
