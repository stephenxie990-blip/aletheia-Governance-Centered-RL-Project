# trust主合同切换实现验证-2026-03-16-1657

## 一、这轮实现的目标

把 actor-side 从“多层乘法门控叠加后的弱修正”收缩到一个更干净的主合同：

- `semantic_pressure = max(semantic_certified_mismatch, inflation_pressure)`
- `trust = clamp(1 - corridor_mask * semantic_pressure, trust_floor, 1)`
- `corridor_semantic_blend_beta = 1 - trust`

核心约束：

1. `trust` 成为 corridor semantic blend 的唯一主 actuator
2. `clean target / rebind / support / confidence` 退回观测与审计层
3. 不再新增 `actor_contract_analytic_scale` 乘法收缩，避免再次把主效应稀释掉

## 二、这轮实际改了什么

### 1. 配置与入口

- 在 `aletheia/aletheia_config.py` 新增：
  - `adaptive_imag_actor_contract_trust_floor`
- 在 `aletheia/aletheia_api.py` 新增默认 override：
  - `adaptive_imag_actor_contract_trust_floor = 0.2`

### 2. `_build_imagined_batch()` 主逻辑

- 删除旧的 `negative-adv corridor blend` 直接驱动 `corridor_semantic_blend_beta` 的路径
- 保留 corridor / clean target / certified mismatch / inflation 的观测量构造
- 新增：
  - `actor_contract_semantic_pressure`
  - `actor_contract_semantic_trust`
- 将：
  - `corridor_semantic_blend_beta`
  改为只由 `trust` 派生

### 3. clean target 与 rebind 的职责边界

- `clean target replacement` 不再直接改写 `target_actor`
- `corridor_semantic_target_preview` 仅用于 audit preview
- `actor_contract_rebind_alpha` 继续计算，但仅保留为 audit telemetry
- `actor_contract_analytic_scale` 保持 `ones`，不再作为新的 actor-side 乘法 actuator

### 4. 测试契约

- 把旧的“clean target 会直接下拉 target_actor”测试重写为：
  - 只验证 audit preview 有效
  - 验证 `target_actor` 本体不被 direct rewrite
- 把 actor-contract 测试重写为：
  - `semantic_pressure > 0`
  - `trust < 1`
  - `corridor_semantic_blend_beta` 被抬升
  - `weighted_actor_target_mean` 被压低

## 四、这轮结论

### 已经修对的部分

1. actor-side 主合同不再依赖一长串乘法门控才能获得作用
2. `trust` 已经成为 `corridor_semantic_blend_beta` 的唯一直接来源
3. `clean target / rebind / confidence / support` 已成功退回观测与审计层
4. `weighted_actor_target_mean` 已被纳入 `trust` 驱动的直接验证链

### 还没有修的部分

1. `base_actor` 仍然没有被 clean-aware 替换
2. `compute_dreamer_actor_loss()` 的主公式本身没有改，只是换了 `corridor_semantic_blend_beta` 的来源
3. 系统里仍存在独立于本次主合同切换之外的保护支路

## 五、一个必须说明的边界

本轮“trust-only”成立的准确表述是：

> `trust` 已成为 corridor semantic blend 这一条 actor 主合同切换链的唯一主 actuator。

但它不等于：

> 系统里已经不存在任何别的目标修复或保护逻辑。

当前仍需明确区分的一条独立支路是：

- `aletheia/aletheia_train.py` 中 persistence-tail repair 逻辑
- 它仍可能在 tail slice 上局部改写 `target_actor` 或 `weights_actor`
- 这条链属于 post-trigger / persistence 保护面，不属于这次 `trust-only v1` 主合同重写范围

因此，下一轮如果做真实 run 解释结果，必须分清：

1. `trust-only` 是否修动了 corridor semantic blend 主链
2. persistence / tail repair 是否在晚期同时参与了结果塑形

## 六、下一步最合理的检查点
