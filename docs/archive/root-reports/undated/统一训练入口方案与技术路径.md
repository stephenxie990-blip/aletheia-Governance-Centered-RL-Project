# 统一训练入口方案与技术路径

> 说明：这份文档已经吸收原 `统一训练入口方案.md` 的重复内容，作为该主题在 `undated/` 归档区的唯一保留正文。

## 目标
建立“唯一训练入口 + 多脚本接入”的统一训练体系：
- 输入统一：训练脚本统一进入同一在线环境入口进行规范化、适配、自适应维度转换
- 训练启动统一：训练循环只在统一入口内部触发
- 输出统一：summary.json / eval_history.jsonl / config_resolved.json 统一由入口写出

## 设计原则
- 脚本入口保留：继续支持 python 123.py / python 321.py 启动
- 入口唯一：所有脚本最终只调用 run_train()
- 逻辑集中：训练、评估、保存、门禁只在 run_train() 内实现
- 输出一致：所有任务产物格式一致，便于回归与对比

## 统一入口位置
- 统一入口函数放置在 aletheia_api.py 中：run_train()
- 作为唯一可复用训练入口，脚本只负责“解析参数 + 调用 run_train()”

## 输入统一策略
统一入口 run_train() 负责：
- 接收 env_id（在线环境）或显式 env / env_factory
- 接收 adapter（自适应感知系统入口）
- 将输入标准化为统一结构（obs / action / reward / next_obs / done）
- 进行维度检查与自适应转换后进入训练流程
- `dataset_path` 当前未实现，调用时会明确抛出 `NotImplementedError`，避免误导为已支持离线训练

## 训练启动统一策略
run_train() 内部负责：
- 创建或加载 agent
- 构建 TrainingConfig
- 创建/恢复 buffer
- TrainingLoop.run() 作为唯一训练启动点
- eval_fn / save_fn 在内部统一

## 输出统一策略
run_train() 负责生成：
- config_resolved.json：包含完整 args、overrides 与 TrainingConfig.to_dict
- eval_history.jsonl：每次 eval 记录 step/mean/std/min/max/mean_length
- summary.json：final_current、final_best、best_eval_step、stats

## 脚本接入规范
所有训练脚本（如 123.py / 321.py）应满足：
- 解析参数 → 直接调用 run_train()
- 不包含训练循环、评估逻辑、保存逻辑
- 参数仅负责转换为 run_train() 需要的输入结构

## 脚本边界
- 正式训练入口：`scripts/cartpole_train.py`
- 历史实验/调试脚本 `scripts/cartpole_mbrl_full.py`、`scripts/cartpole_test.py`、`scripts/cartpole_imagination_test.py` 已在后续退役批次中从活跃脚本面移除
- 正式回归、评估、resume 语义都以 `run_train()` 为准

## 技术路径
1. 在 aletheia_api.py 中新增 run_train() 统一入口
2. 将现有 cartpole_train.py 的训练主逻辑迁移到 run_train()
3. cartpole_train.py 改为薄脚本（仅参数解析 + run_train 调用）
4. 新脚本（123.py / 321.py）遵循统一接入规范
5. 输出一致性校验：summary / eval_history / config_resolved 格式固定

## 预期效果
- 入口唯一，逻辑集中
- 输入输出一致，便于稳定性工程与回归门禁
- 新环境接入仅需写脚本壳，不重复训练逻辑
