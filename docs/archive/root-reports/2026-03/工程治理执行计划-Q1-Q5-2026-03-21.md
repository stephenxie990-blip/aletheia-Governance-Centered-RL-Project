# 工程治理执行计划（Q1-Q5）

## 总体目标
- 把 SAI 工程边界收敛到三层：`contracts/*`、`training/compensation.py`、最小训练运行时。
- 把 legacy/compat/scaffold 从“分散混住在主训练链”收敛为“先集中、再切断、再删除”的受控过程。
- 每一阶段都必须先过结构验收，再决定是否进入下一阶段，不允许再靠连刀试错推进。

## 固定工作流
- 使用 skills：
  - `pi-planning-with-files`：落盘阶段计划、发现、进度和调整记录。
  - `agentic-engineering`：按单一主风险拆批，先定义完成条件再实施。
  - `verification-loop`：每批执行 compile、focused tests、差异审查。
- subagent 分工建议：
  - `Harvey`：`aletheia_train.py` 内脚手架分块、迁移优先级、live runtime 耦合分析。
  - `Carver`：`config/api/tests/world_model/foundation` 的 legacy/compat 面清单与删除门禁。
  - `Hilbert`：resume/checkpoint/export/restore 协议迁移与断点续跑风险。
- 主进程职责：
  - 决策唯一主线。
  - 执行代码修改。
  - 做阶段审查与是否进入下一阶段的裁决。

### 范围

### 负责人建议

- 审查辅助：`Harvey`

### 验收标准
- `compileall` 通过。
- `test_semantic_contract`、`test_contract_convergence` 通过。
- 训练行为不因 stage 归一化迁移而发生口径变化。

## Q2
### 目标
- 切断主训练文件对旧 stage/scaffold 定义权，只保留调用权。

### 范围
- `_resolve_imag_controller_stage` 周边旧阶段语义集中迁移到 `_scaffold/`
- train 顶部 helper alias 按域收口，只保留 canonical 入口

### 负责人建议
- 主负责人：主进程
- 审查辅助：`Harvey`

### 验收标准
- `aletheia_train.py` 不再持有分散 stage alias/compat 壳定义。
- `_scaffold/` 成为唯一旧阶段集中区。
- focused `training_loop_integration` 回归通过。

## Q3
### 目标
- 删除显式 legacy/compat 层，但不打断当前正式产物协议。

### 范围
- `semantic_contract.py` 已物理删除
- `aletheia_api.py` / `aletheia_config.py` 的外部 legacy override 面改为明确治理边界
- `aletheia_foundation.py`、`aletheia_world_model.py` 中纯 alias 类弃用入口清退

### 负责人建议
- 主负责人：主进程
- 审查辅助：`Carver`

### 验收标准
- 外部入口不再默默适配旧合同。
- legacy 名称只允许存在于“协议迁移中仍必须识别”的单点位置。
- 相关 focused tests 更新并通过。

## Q4
### 目标
- 删除 `_scaffold/` 中不再属于最小运行时的旧阶段机与救火逻辑。

### 范围
- `fallback / handoff / rescue / latch / bypass / post_entry / persistence_release` 等旧分支

### 负责人建议
- 主负责人：主进程
- 审查辅助：`Harvey`

### 验收标准
- live runtime 只剩最小控制阶段：`idle / trigger / persistence / post_solved`
- 不再有旧阶段导出的运行时观测面
- focused runtime tests 和一轮真实基线 run 通过

## Q5
### 目标
- 完成产物协议与测试面的终局收口，删除最后残留 legacy。

### 范围
- `MinimalCompensationState` 的 legacy payload 出口替换为 canonical payload
- resume/checkpoint/export/restore 协议切换
- 旧兼容测试退场，保留新协议 roundtrip 验证

### 负责人建议
- 主负责人：主进程
- 审查辅助：`Hilbert`

### 验收标准
- checkpoint/resume 使用 canonical compensation payload
- 历史 legacy 协议如不再支持，需在入口显式报错，不允许 silent fallback
- compile + focused tests + 一条真实 baseline gate run 通过

## 推荐顺序
1. Q1：先收边界，把定义迁出去。
2. Q2：再切主训练文件的定义权。
3. Q3：删除纯 compat/shim/alias。
4. Q4：砍掉 `_scaffold/` 中不属于最小运行时的旧阶段机。
5. Q5：最后切产物协议，完成物理清除。

## 阶段审查规则
- 每阶段结束必须完成：
  - `./.venv/bin/python -m compileall aletheia`
  - 该阶段对应 focused unittest
  - 变更文件人工审查
- 审查后只允许三种结论：
  - `pass`：进入下一阶段
  - `pass_with_adjustment`：记录调整后再进入下一阶段
  - `hold`：停在当前阶段修复，禁止扩刀

## 过程监管要求
- planning files 必须同步记录：
  - 本阶段目标
  - 已完成修改
  - 验收结果
  - 下一阶段是否确认或调整
- 非 git 环境下，回滚依赖：
  - 批次文档
  - focused 验收
  - 保守补丁
