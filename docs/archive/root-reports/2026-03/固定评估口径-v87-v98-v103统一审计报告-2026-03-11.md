## 4. persistence 纯 imag 稳定性重新拆解

### 4.1 v98 的问题不是“想象坏掉”，而是“过度保守”
- `v98` 的 imagined consistency 其实优于 `v103`：
  - 更高 `continue_prob_mean`
  - 更小 `value_target_gap_abs_mean`
  - 更大的 `weights_min`
- 但它长期停留在：
  - `cap=0.93`
  - `post_trigger_scale=0.97`
  - `critic_multiplier=1.75`
- 结论：`v98` 更像是 persistence 内部仍被 post_entry 风格保护压住，策略过于保守，无法把更干净的 imagination 兑现成高真实回报。

### 4.2 v103 的问题不是“完全不会利用 imagination”，而是“利用方式过窄”
- `v103` 比 `v98` 的真实回报更高，但 imagined rollout 质量明显更差：
  - `continue_prob_mean 0.735 < 0.902`
  - `gap_abs 6.28 > 2.91`
  - `weights_min ~ 0`，说明大量 imagined branches 被压成几乎零权重
- 同时它又更激进：
  - persistence 阶段 `cap≈0.86`
  - `post_trigger_scale≈0.8`
  - `negative_adv_guard` 被关闭
- 结论：`v103` 不是学到了更稳的世界模型，而是把 actor 收缩到少数能在当前真实动力学上工作的狭窄行为区域，形成“窄策略 exploitation”。

### 4.3 v103 高方差的直接机制
- `v103` 的 imagined tail 明显塌得更厉害：
  - tail `continue_profile` 只剩 `0.238`
  - tail `return_profile` 只有 `~4.0`
- 但它的 `value_profile` 却在后段继续上升到 `13+`。
- 这说明 persistence 内部存在明显的 tail mismatch：
  - imagined continue / returns 在后半段快速失真或过早悲观终止
  - critic / value 仍保持较高基线
- 结果是：
  - `adv_mean` 长期显著为负
  - 大量 branch 权重塌到近零
  - actor 更新只来自少量 surviving branches
- 这种训练信号天然会导致：
  - 对少数起始状态有效
  - 跨初始 seed 波动大
  - 容易出现单 seed 高分、总体均值一般的“窄策略高方差”现象

### 4.4 v87 solved 几何为什么不同
- `v87` 既没有像 `v98` 那样过度保守，也没有像 `v103` 那样 tail 崩坏：
  - `cap=0.86`，具备足够 exploitation 空间
  - `negative_adv_guard_active=1.0`, `critic_multiplier=1.5`，保持 critic 纠偏
  - `continue_prob_mean≈0.887`，显著高于 `v103`
  - `weights_min=0.0038`，没有塌成近零
- 这意味着 solved persistence 需要的是“受控 exploitation”：
  - 可以把 cap 拉到 `0.86`
  - 但必须同时维持较高 continue 和足够的 critic/negative-adv 纠偏

## 5. 修复重点重排

### 不应继续作为主线的方向
- 继续追 `v103 late-lift`
- 单纯增加 `midwater boost`
- 单纯把 unresolved persistence_escape 调顺

### 新主线
1. 以 `v87` 为 solved 几何参考，重建“低 cap + 高 continue + 有 critic 纠偏”的 persistence 区间。
2. 避免 `v98` 式过度保守：不要让 `cap=0.93`、`actor_scale=0.97`、`critic_multiplier=1.75` 长期钉死。
3. 避免 `v103` 式 tail mismatch：重点修 persistence 内部的
   - continue tail collapse
   - value/return tail 脱钩
   - branch weights 近零塌缩
4. 下一轮算法重点应放在 persistence 内部的 tail 纠偏，而不是 post_entry 入口继续调参。
