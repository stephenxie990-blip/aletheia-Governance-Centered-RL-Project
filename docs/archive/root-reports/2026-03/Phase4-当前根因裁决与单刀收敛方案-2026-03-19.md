## 0. 2026-03-19 晚间补充裁决

`Phase 4.13` 已经完成一次“修实现漏洞”和一次“严格真实复验”。

- 第一版 `v230` 的问题不是行为本体，而是 helper 语义不满足合同：
  - `consumer_window_activation == 0` 时，只要 `hold_gate > 0`，最终 `consumer_retained` 仍会偏离 `hold_persisted`。
  - 这意味着 `Phase 4.13` 在 `late_gate <= 0.9` 之前并不真正中性。
- 修正后再次真实运行，修复版 `v230` 与 `v229` 在 `1250/1500/1750/2000/2250/2500` 的行为和核心结构指标几乎完全一致：
  - `1250 = 194.2`
  - `1500 = 158.8`
  - `1750 = 490.4`
  - `2000 = 184.2`
  - `2250 = 160.8`
  - `2500 = 257.4`
- 同时修复版 `v230` 还新增确认了一条更重要的事实：
  - `2000-2500` 时 `consumer_window_activation = 1.0`
  - 但 `consumer_delta_abs = 0.0`
  - 说明 `Phase 4.13` 在正确语义下是 **inert**，不是主要增益来源

因此，当前正式裁决更新为：

> `Phase 4.13` 不是下一刀。
> 它修复的是“final consumer 提前侵入”的实现漏洞，但没有证明“consumer retention strengthening”本身是有效增益层。

`Phase 4.14` 随后也完成了严格真实运行，结论已经进一步锁定：

- `v231` 不是 inert：
  - `2250` 时 `hold_gate = 0.0291`，高于 `v229 = 0.00373`
  - `2250` 时 `hold_delta_abs = 0.4748`，高于 `v229 = 0.0676`
  - 说明这刀确实把 `Phase 4.8` 的 hold persistence 推强了
- 但行为与终局误差没有因此变好，反而更差：
  - `1500 = 47.2`，低于 `v229 = 158.8`
  - `2250 = 138.8`，低于 `v229 = 160.8`
  - `2500 = 143.8`，低于 `v229 = 257.4`
  - `2500` 时 `real_mc_value_gap_abs_mean = 20.3506`，高于 `v229 = 14.6976`

因此，`v231` 的正式含义不是“力度还不够”，而是：

> 单纯继续增强 `Phase 4.8 hold persistence` 的 retention strength，会把 late-window bonus value 更稳定地保留在一个并不更 terminal-true 的状态上。
> 所以下一刀仍然只能留在 `Phase 4.8`，但不再允许做单纯的 effectiveness strengthening。

## 1. 最终裁决

当前 Phase 4 的问题已经收敛成两层，而且两层不能混在一起说。

### 1.1 已经稳定的层：执行底座

以下链路已经不再是主故障点：

- `Phase 4.2` 的 authority floor 执行链
- `Phase 4.5` 的 first-drop safe activation
- `Phase 4.9/4.10` 之后的 late-window entry 恢复
- `Phase 4.11` 的 terminal-truth candidate family 修正
- `Phase 4.12` 的 terminal activation 边缘失活修正

`v229` 的直接证据：

- `critic/critic_contract_bootstrap_floor_shortfall_on_valid_mean = 0.0`
- `contract/bootstrap_external_authority_shortfall_on_valid_mean = 0.0`
- `1250` 时：
  - `eval = 194.2`
  - `late_gate = 0.7388`
  - `terminal_activation = 0.0`
  - `terminal_bridge = 0.0`
- `1750/2000/2250/2500` 时：
  - `late_gate` 已经正常抬起
  - `terminal_activation` 不再长期卡死在 `0`
  - `2250/2500` 时 `late_gate = 1.0`

这说明：

- 机械执行底座已经基本稳定。
- 我们现在面对的，不再是“合同进不去”或“floor 守不住”。

### 1.2 还没有稳定的层：hold persistence 本体

虽然晚窗已经能进入、也能把 terminal-truth candidate 接进来，但真正决定“保留什么、在什么条件下继续保留”的，仍然是更上游的 `Phase 4.8 hold persistence` 本体。

`v229` 与修复版 `v230` 的共同证据不是 `late_gate`，而是这组比例失衡：

| step | eval | late_gate | terminal_delta_abs | hold_gate | hold_delta_abs |
| --- | ---: | ---: | ---: | ---: | ---: |
| `1750` | `490.4` | `0.7815` | `0.0598` | `0.00718` | `0.00006` |
| `2000` | `184.2` | `1.0` | `14.0403` | `0.01522` | `0.2004` |
| `2250` | `160.8` | `1.0` | `18.3375` | `0.00373` | `0.0676` |
| `2500` | `257.4` | `1.0` | `16.2071` | `0.00305` | `0.0491` |

这组数据表明：

- terminal-truth source 已经在晚窗里被算出来了，而且偏移量很大。
- 但 `hold_persistence` 真正把它吃进去、留住的幅度仍然很小。
- 修复版 `v230` 又进一步证明：
  - `consumer_window_activation` 就算到了 `1.0`
  - `consumer_delta_abs` 仍然可以保持 `0.0`
  - 说明 final consumer strengthening 不是当前主矛盾
- `v231` 又进一步证明：
  - 单纯把 `hold persistence` 推强，并不会自动带来更好的 late-window terminal truth
  - 在真实退化窗口里，更强的 hold 反而可能把一个偏掉的 bonus value base 保留得更稳定
- 也就是说，现在不是“没有 semantic source”，也不再只是“消费力度不够”，而是 `Phase 4.8` 还缺少 selective retention / degradation-aware release。

因此，当前真正的根因不是：

- actor 路线不对
- controller stage 不对
- final effective-contact surface 不对
- authority floor 不对
- trigger entry 还没恢复
- terminal-truth candidate family 仍然完全错

当前真正根因更新为：

> `late-window fully-active` 以后，`floor-above bonus` 的真正主故障点已经收敛到 `Phase 4.8 hold persistence` 本体。
> 但这个故障点的准确形态已经更新为：系统缺少对真实退化窗口的 selective retention / degradation-aware release。
> 当前主问题不是“hold 不够强”，而是“高退化窗口里会更稳定地保留一个并不更 terminal-true 的 bonus value”。

## 2. 底座是否稳定

### 2.1 稳定的部分

现在可以明确判定“稳定”的，是下面这些层：

- floor/contact/authority 执行底座稳定
- first-drop 保护窗稳定
- late-window entry 恢复后不会再次全零失联
- terminal activation 阈值边缘不会再像 `v228` 那样在 `0.8` 左右来回掉空

这意味着我们不再是在“表面刷指标”的阶段。
执行底座已经从脆弱平衡点，进入了可复现、可解释的结构稳定态。

### 2.2 还不稳定的部分

还没有稳定的是：

- fully-active late-window 下，`hold_persisted value` 对 `terminal-truth source` 的保留是否既有效又有选择性
- 高真实退化窗口里，系统是否会错误地继续保留一个已经不够 terminal-true 的 bonus value
- `hold_delta_abs` 变大时，行为与 `real_mc_value_gap_abs_mean` 是否同步改善，而不是出现 `v231` 这种“保留更强但终局更差”的反证

换句话说：

- 机械底座已经稳了
- 语义底座还没有完全稳

## 4. 单刀方案

下一刀的正式目标固定为：

## `Phase 4.15：Late-Window Hold Persistence Selective Retention / Degradation-Aware Release`

对应的实现前合同文档固定为：

`Phase4-15-Degradation-Aware-Release-Contract-2026-03-19.md`

### 4.1 目标

只修一件事：

> 当 `late_gate` 已经 fully active，且 terminal-truth source 已经被解析出来后，让 `Phase 4.8 hold persistence` 本体真正把这份 semantic bonus value 吃进去，并在 `2000-2500` 持续保留。
>
> 更新后的唯一目标是：
> 只在 semantic health 仍成立时保留这份 bonus value；一旦真实退化持续恶化，就要能及时释放错误或过时的 hold，而不是继续把它留在最终 bootstrap value 中。

### 4.2 要修的不是谁

这一刀不是：

- 继续修 trigger entry
- 继续修 terminal activation
- 继续换 candidate family
- 继续增强 authority
- 继续调 floor

### 4.3 要修的就是谁

这一刀只修：

- `bonus value hold persisted`
- 对 `terminal_truth_source` 的选择性保留
- `late-window hold persistence` 的 degradation-aware release

从 `v229-v231` 的联合证据看，最值得盯住的已经不是单独把 `hold_delta_abs` 做大，而是下面这组联立关系：

- `hold_delta_abs`
- `eval`
- `real_mc_value_gap_abs_mean`

因为现在的问题不是 terminal source 没来，而是：

- 它来了以后，什么时候该保留、什么时候该释放，还没有被 `Phase 4.8` 正确表达
- `v231` 已经证明“只做更强保留”会把系统推向错误方向

---

## 5. 单刀后的通过标准

下一刀只按下面这组标准裁决，不再混入别的目标。

### 5.1 结构标准

必须同时满足：

- `critic/critic_contract_bootstrap_floor_shortfall_on_valid_mean == 0.0`
- `contract/bootstrap_external_authority_shortfall_on_valid_mean == 0.0`
- `1250` 时：
  - `terminal_activation_bridge_mean == 0.0`
  - 不允许 early-safe 回归
- `2000-2500` 时：
  - `late_gate > 0.0`
  - `terminal_activation_mean > 0.0`
  - `terminal_truth_delta_abs_mean > 0.0`
  - 不再把“单独增大 `hold_delta_abs_mean`”作为通过标准
  - 要求 `hold` 路径的变化不能再伴随 `real_mc_value_gap_abs_mean` 恶化为 `v231` 形态
  - `consumer_delta_abs_mean` 不再作为主通过标准，因为修复版 `v230` 已证明该层可完全 inert
- 当 `real_reward_degradation` / `real_task_cert_gate` 明显恶化时，hold 路径必须出现可观测收缩或释放，而不是继续稳定放大

### 5.2 行为标准

这一步不要求刷新 `1750` 的峰值纪录，重点看后段保留是否更稳、且不再被错误 hold 拖垮：

- `eval@1250 >= 194.2`
- `eval@1500 >= 158.8`
- `eval@2000 >= 184.2`
- `eval@2250 > 160.8`
- `eval@2500 > 257.4`

### 5.3 失败分流

如果失败，只允许按下面方式解释：

- 如果 `hold_delta_abs` 变高，但 `2250/2500` 行为和 `real_mc gap` 同时变差：
  - 说明问题已经不是“hold 不够强”，而是 `Phase 4.8` 缺少 selective retention / degradation-aware release
- 如果 `terminal_delta_abs` 仍高，但 hold 路径在高退化窗口不会释放：
  - 说明问题确定在 hold persistence 本体，不再回头怀疑 candidate / trigger / floor
- 如果 `1250` 回归：
  - 说明 hold-strengthening 侵入 early-safe window，回调 hold 消费窗口，但不动其他层
- 如果 `late_gate` 再次失效：
  - 先检查运行口径与装配链，不直接改公式

## 6. 最终结论

Phase 4 当前的最终裁决可以固定写成一句话：

> 机械底座已经基本稳定；当前唯一没有稳定下来的，是 `late-window fully-active` 之后 `floor-above bonus` 对 terminal-truth source 的最终消费与持续保留。

因此，后续只允许继续动：

> `Phase 4.8 hold persistence` 这一层

不再允许横向扩散到 actor、controller、floor、entry、bridge、candidate family 或 trigger source。

这就是当前最小、最窄、最干净的一刀。
